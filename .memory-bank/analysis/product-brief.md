# Product Brief: кухонные часы с погодой и таймерами

## Metadata
- Status: draft
- Decision: proceed
- Source artifacts:
  - [`IDEA.md`](../../IDEA.md): подробный пользовательский Design Brief и границы V1.
  - [.memory-bank/analysis/brainstorming/BR-001.md](brainstorming/BR-001.md): принятые решения по температурной палитре и pseudo-glass погодных карточек.

## One-liner
Персональное Android-приложение, превращающее постоянно включённый кухонный смартфон в хорошо читаемые издалека часы с погодой и тремя быстрыми таймерами.

## Target Users
- Основной пользователь: владелец приложения, использующий выделенный смартфон стационарно на кухне.
- Контекст: горизонтальный экран на расстоянии, частые короткие взгляды и управление таймерами одним касанием.

## Problem
- На кухне нужны крупные постоянно видимые часы, краткая погода и быстрый запуск таймера без переключения между отдельными приложениями.
- Обычный телефонный UI требует лишних действий и плохо читается издалека.
- Кухонный таймер должен продолжать корректный отсчёт вне foreground и после временной остановки процесса приложения.

## Current Alternatives
- Конкретные используемые сейчас альтернативы в source artifact не зафиксированы.
- Предполагаемая заменяемая комбинация — системные часы, отдельное погодное приложение и отдельный таймер; это требует подтверждения при PRD clarification, но не меняет границы продукта.

## Value Proposition
- Один спокойный полноэкранный интерфейс даёт время, погодный контекст и таймеры без навигационного шума.
- Главные часы читаются издалека, а наиболее частое действие — запуск preset-таймера — выполняется одним нажатием.
- Явные состояния активного и просроченного таймера снижают риск пропустить завершение или случайно отменить отсчёт.

## Product Concept
- Fullscreen landscape clock на чёрном фоне с доминирующими голубыми цифрами.
- Слева — город, дата и четыре яркие погодные карточки с Windy-derived температурными цветами; справа — три цветные неоновые кнопки preset-таймеров.
- Температура и стрелки давления используют общий статичный pseudo-glass без realtime blur; силу эффекта пользователь регулирует в Settings с live preview.
- Активный таймер занимает область часов, а после завершения превращается в крупное звуковое и визуальное состояние, отключаемое касанием.
- Погода поступает из Yandex Weather API v2, сохраняется локально и остаётся доступной до 24 часов без интернета.

## MVP Scope
- Часы `HH:mm`, дата и выбранный город на основном экране.
- Четыре погодные карточки: вчера, сегодня, завтра и послезавтра.
- Локальная семидневная история погоды и тренд давления.
- Отдельный прогноз на 14 дней.
- Явная per-degree палитра для целых температур от −30 до +47 °C с clamp за пределами диапазона.
- Прозрачные pseudo-glass температура и стрелки давления; один slider силы эффекта с начальным значением 0.45 и live preview погодной карточки.
- Три независимо настраиваемых preset-таймера; одновременно активен только один.
- Надёжный отсчёт вне foreground, визуальная просрочка и повторяющийся звуковой сигнал.
- Настройки API key, страны/города, длительностей таймеров, звука, громкости и силы glass-эффекта.

## Non-goals
- Публикация приложения и распространение APK в V1.
- Backend или общий встроенный Yandex Weather API key.
- Google Services, автозапуск после reboot и pixel shifting для AMOLED.
- Получение погодной истории за период до установки.
- Telegram-бот и Android TTS: идея отложена до V2.
- Любые функции и настройки, не описанные в source artifact.

## Success Metrics
- На целевом экране 1280×720 время остаётся главным элементом и читается издалека.
- Каждый preset-таймер запускается одним нажатием, не отменяется одиночным касанием во время отсчёта и сохраняет корректное время вне foreground и после временной остановки процесса.
- Завершение таймера невозможно пропустить при доступном звуке: показывается полноэкранное состояние и сигнал длится до ручного отключения, но не более 30 минут.
- При актуальных данных пользователь видит четыре различимые погодные карточки; после 24 часов без обновления они переходят в согласованное пустое состояние.
- Каждой целой температуре в диапазоне −30…+47 °C соответствует воспроизводимый цвет из принятой таблицы; значения вне диапазона используют ближайший крайний цвет.
- Настройка glass intensity сразу отражается на preview с сегодняшней температурой либо fallback 24 °C и сохраняется после изменения.
- Основной сценарий не требует сети для часов, таймеров и показа сохранённой погоды моложе 24 часов.

## Constraints
- Персональное Kotlin Android-приложение для Samsung GT-I9300I (`s3ve3gds`) с планируемым Android 11.
- Единственная согласованная ориентация — landscape; основной язык интерфейса — русский.
- Экран остаётся включённым, системные панели скрыты, основной UI неподвижен.
- Погода: Yandex Weather API v2; личный API key вводится пользователем и хранится локально, но не встраивается в APK.
- Выбор страны и города должен по возможности работать offline и не использовать Google Services.
- Точная визуальная геометрия должна быть подобрана под 1280×720 с сохранением доминирования часов и композиции source artifact.
- Все 78 цветов палитры хранятся явно в одном легко редактируемом compile-time source; runtime-интерполяция не используется.
- Pseudo-glass строится статичными прозрачным fill и светлой/тёмной кромками без backdrop blur, refraction, background capture и постоянной анимации.

## Assumptions
- Устройство действительно будет работать на совместимой Android 11 custom ROM; это нужно подтвердить до архитектурных решений о фоновой работе.
- Приложение предназначено для одного владельца и не требует account, cloud sync или multi-user сценариев.
- Пользователь принимает неподвижный UI и отсутствие специальной защиты AMOLED от выгорания.

## Risks
- Ограничения Android 11 и конкретной custom ROM могут влиять на длительный background timer, сигнал и восстановление после остановки процесса.
- Полнота и размер offline-справочника городов могут конфликтовать с ресурсами старого устройства.
- Фактическая доступность нужных полей Yandex Weather API определит mapping погодных состояний, ночной прогноз, фазу Луны и 14-дневные данные.
- Яркие карточки и прозрачные glass-цифры могут потребовать визуальной проверки на целевом экране, чтобы не ослабить доминирование часов и читаемость температуры.
- Неподвижный постоянно включённый экран создаёт принятый пользователем риск AMOLED burn-in.

## Open Questions
- Как называется приложение?
- Каковы источник и требуемая полнота offline-справочника стран и городов?
- Что делает короткий тап по уже выбранному городу?
- Как реагирует карточка «Послезавтра», если 14-дневный прогноз недоступен?
- Как сигнал таймера взаимодействует с silent mode и Do Not Disturb?
- Какой набор встроенных сигналов входит в V1?
- Как должны выглядеть settings и ошибки API?
- Какие дополнительные элементы, если они действительно нужны в V1, входят в левую область экрана?

## PRD Input Summary
- Сформировать V1 для одного стационарного kitchen display, сохранив приоритет «время прежде всего» и минимальное число действий.
- Сохранить принятую Windy-derived таблицу температурных цветов и KISS-реализацию регулируемого pseudo-glass как входные продуктовые решения.
- Уточнить открытые продуктовые и platform decisions без расширения уже зафиксированного V1.
- Отдельно проверить реализуемость background timer и необходимых полей Yandex Weather API на целевой платформе.
- Зафиксировать acceptance criteria для состояний main screen, weather freshness, countdown, overdue alert, forecast, settings и device-preview палитры/glass.
