description: Minor workflow friction observed during the provider-migration planning session.
---

- A discovery command included the optional `app/src/androidTest` root, which is absent and caused `rg` to emit a non-blocking “No such file or directory” diagnostic. Future discovery should enumerate existing `app/src/*` roots first.
- FT-007's feature filename is `FT-007-overdue-alert.md`, while its implementation-plan title uses “overdue state and alert”; guessing the path from that title caused one non-blocking missing-file read. Future feature reads should resolve paths from `.memory-bank/features/index.md` first.
- A read-only `rg` pattern containing Markdown backticks was passed inside a double-quoted shell command, so Bash attempted command substitution and emitted two harmless “command not found” diagnostics. Future shell patterns containing backticks should be single-quoted or passed without shell interpretation.
- The authoritative task index is JSON at `.memory-bank/tasks/index.json`, not Markdown at `.memory-bank/tasks/index.md`; one guessed-path read failed harmlessly. Future task-index access should resolve the path through `.memory-bank/index.md` or repository search first.
- FT-004's feature filename is `FT-004-ten-day-forecast.md`, not the title-derived `FT-004-long-term-forecast.md`; one batched read therefore emitted a harmless missing-file diagnostic. Feature paths should always come from `.memory-bank/features/index.md`.
- A multi-file decision-log patch assumed stale `last_updated` values for FT-002–FT-004 and failed atomically at precondition verification. Future reconciliation patches should read each frontmatter value immediately before constructing shared hunks.
- The system `ajv` default constructor did not preload the Draft 2020-12 meta-schema used by `task.schema.json`, so an extra read-only schema check failed before validating tasks. Use `ajv/dist/2020` for this repository's task schema.
- An extra link checker initially treated task `source_artifacts` AC locators as literal GitHub fragments. These locators intentionally identify the heading's stable AC prefix while canonical `normative_inputs` use exact Markdown anchors; validators should check the two conventions separately.
- The first AC/REQ checker stopped only at the next level-3 heading, so the final AC in a feature absorbed later level-2 sections and produced a false extra-REQ failure. AC block parsing must stop at the next Markdown heading of level 1–3.
