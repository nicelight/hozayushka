## Подтверждённые findings

### TD-W12-001 — Mixed-wave dirty worktree снижает bounded attribution

- Evidence: W12 preflight прямо фиксирует сохранённые unrelated dirty
  `task/scheduler/review/papercut` changes
  (`.protocols/TASK-015-T3-FT-001-W12/progress.md:12-16`), а текущий
  `git status --short` одновременно содержит W12 source/test, Memory Bank,
  scheduler status, W11 defect note, review report и отдельные papercut-файлы.
  При этом независимая проверка подтверждает, что production/test diff самой
  реализации ограничен двумя ожидаемыми файлами
  (`.protocols/TASK-015-T3-FT-001-W12/verification.md:90-99`).
- Impact: repository-level build, unit, lint/doctor и diff receipts нельзя
  безопасно переиспользовать как полностью изолированный W12 результат без
  повторной проверки или реконструкции baseline; attribution между W11/W12 и
  workflow sync остаётся дороже и менее надёжно.
- Priority: medium — это process/repository debt, не подтверждённый product
  defect в W12 code path.
- Owner/route: workflow/repository owner; перед следующей wave создать clean
  checkpoint либо эквивалентный isolated worktree и записать W12-owned delta.
  Текущий W12 task/status/history менять не требуется.

- Evidence: task contract требовал fresh RED для non-city double-tap и отдельной
  baseline-проверки city hold (`.memory-bank/tasks/TASK-015-T3-FT-001-W12.task.json:40-49,71-74`).
  Фактический pre-change run показал non-city double cancellation и city
  hold → Settings → Back уже до изменения; исторический W11 failure честно не
  был backfilled как RED
  (`.protocols/TASK-015-T3-FT-001-W12/progress.md:31-35`,
  `.tasks/TASK-015-T3-FT-001-W12/attempt-1-prechange.md:28-50`,
  `.protocols/TASK-015-T3-FT-001-W12/verification.md:31-39`).
- Impact: fresh GREEN доказывает итоговое наблюдаемое поведение, но не
  изолирует causal value W12 repair относительно текущего baseline и не
  показывает, что именно этот diff устранил воспроизводимый failure. Для
  следующих gesture changes это повышает стоимость regression attribution и
  оставляет uncertainty о необходимости конкретной коррекции.
- Priority: medium — evidence/verification debt, не функциональная W12
  regression; semantic verification всё равно зафиксировала `semantic-pass`.
- Owner/route: будущий FT-001 planning/runtime-verification owner; в следующем
  аналогичном indexed change до production edit получить воспроизводимый
  public RED либо заранее оформить accepted baseline decision. W12 не
  переоткрывать.

### TD-W12-003 — Generic AVD/top-activity probe остаётся операционно шумным

- Evidence: обязательный `dumpsys activity top` завершился с exit 0, но его
  hierarchy была stale и указывала на launcher; MainActivity пришлось
  подтверждать дополнительными `dumpsys activity activities` и `dumpsys window`
  (`.tasks/TASK-015-T3-FT-001-W12/attempt-1-runtime-matrix.md:27-31`,
  `.tasks/TASK-015-T3-FT-001-W12/verifier-owned-evidence-attempt-1.md:57-61`).
  В независимой semantic session AVD/QEMU instability также не позволила
  повторить всю matrix, хотя app failure не наблюдался
  (`.tasks/TASK-015-T3-FT-001-W12/red-verifier-owned-evidence-attempt-1.md:42-48`;
  session papercut: `PAPERCUTS/GPT-5 __ 08-09-2026 00.52.md:3`).
- Impact: runtime gate имеет ложноположительный exit-code signal и требует
  ручной корреляции нескольких dumps/restart-retry; это увеличивает стоимость
  последующей public-touch verification и снижает доверие к одному probe.
- Priority: low — operational papercut, не Android behavior defect в W12.
- Owner/route: Runtime Verification/ADB probe owner; в следующем runtime
  runbook использовать activity/window corroboration как decisive focus check
  при stale `top` и сохранить bounded restart/retry path. Production code W12
  не менять.
