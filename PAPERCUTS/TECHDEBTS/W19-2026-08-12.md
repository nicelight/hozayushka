## Confirmed material findings

### F-01 — live-provider compatibility verification debt (HIGH)

**Evidence.** Production migration now contains the shared HTTP transport and
hand-written JSON boundary at `app/src/main/kotlin/com/hozayushka/app/adapters/weather/WeatherProviderAdapter.kt:173-205`,
Open-Meteo request/parsing at `OpenMeteoWeatherAdapter.kt:15-74` and
OpenWeather request/parsing, subscription/error mapping and transient `appid`
construction at `OpenWeatherWeatherAdapter.kt:20-80`. W18, W19 and the fresh W20
verification all record synthetic/redacted host evidence only and explicitly no
live provider, network or real credential (`W18 S-VERIFY:60-67`; `W19 S-VERIFY:26-34`;
`W20 S-VERIFY:78-86`; W20 task card `:72-74`).

**Impact.** Endpoint reachability, TLS/HTTP behavior, active OpenWeather One Call
3.0 subscription/access, real response variation and runtime error mapping are
not observed. The passed matrices prove provider isolation and normalization
against fixtures, not live compatibility.

**Smallest remediation direction.** When the existing registered runtime route
is authorized, perform one redacted live-provider check with the required
OpenWeather account/key and network; retain the result as `DEFERRED` or observed
pass/fail. No new provider, task or contract is implied here.

### F-02 — target Android/custom-ROM/IME compatibility verification debt (HIGH)

**Evidence.** W20 production behavior depends on Android IME/focus/system-Back
dispatch around `SettingsCapability.kt:659-706,949-955`; the display is a
programmatic layout with fixed geometry anchors in `DisplayCapability.kt:392-415`.
The final W20 VERIFY/RED-VERIFY reports explicitly defer Android framework IME,
target Android 11/custom-ROM, 1280×720 display/audio and lifecycle observations
(`W20 S-VERIFY:78-86`; `W20 S-RED-VERIFY:43-47,93-98`). The runtime contract says
these observations cannot be inferred from host logic
(`.memory-bank/testing/runtime-verification.md:91-145`).

**Impact.** The accepted host PASS does not establish that key commit and refresh
occur through the real IME/focus/back path, or that fullscreen/readability,
temporary interruption, timer rehydration and permitted/suppressed audio work
on the Samsung Android 11 custom ROM at 1280×720.

**Smallest remediation direction.** When an authorized target is available, use
the existing target-device route for those observations and record each outcome
without promoting a generic emulator result to target PASS.
