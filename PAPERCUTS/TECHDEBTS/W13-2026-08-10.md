## Confirmed findings

### TD-W13-001 — Render reuse сохраняет 20 Hz повторный decode и projection build

- **Evidence:** Main Display сохраняет и сравнивает только результат после
  построения input: `renderWeatherCardsIfChanged()` на
  `DisplayCapability.kt:622-629` всё равно вызывает `weather.projection(now)`
  и `settings.settingsPresentationProjection()` на каждом `refresh()`
  (`:712-771`), а один lifecycle-gated ticker продолжает вызывать refresh с
  интервалом 50 ms (`:774-801`). `WeatherCapability.projection()` на
  `WeatherCapability.kt:372-438` каждый раз загружает record; production
  wiring использует `SharedPreferencesWeatherCacheStore` в
  `app/src/main/kotlin/com/hozayushka/app/app/FoundationRuntime.kt:64-69`, а
  `loadRecord()` заново парсит daily, history и hourly serialized values
  (`WeatherCapability.kt:103-135`).
  `MainDisplayWeatherCardRenderer` (`DisplayCapability.kt:205-217`) подавляет
  только `bindWeatherCards()`; это подтверждено единственным
  `removeAllViews`/`addView` site и reuse-тестом в
  `.tasks/TASK-016-T3-FT-001-W13/verifier-owned-evidence.md:33-36,46-58`.
- **Impact:** W13 устраняет duplicate scheduling и дорогостоящий rebuild
  четырёх Android card views, но оставляет чтение/декодирование persisted
  weather state и полную сборку projection на main thread 20 раз в секунду
  даже при неизменном отображении. Это сохраняет материальную нагрузку на
  frame/GC budget и повторную стоимость сопровождения weather-display path;
  на маломощном target это остаётся подтверждённым source-level
  optimization debt, но не доказанным jank или release defect.
- **Priority:** medium.
- **Smallest remediation direction:** в отдельной bounded optimization
  работе отделить обязательный scalar 20 Hz refresh от получения
  display-ready weather input: переиспользовать capability-owned projection
  snapshot и инвалидировать его только при принятом refresh/location или
  необходимом time/freshness boundary, сохранив Weather Context владельцем
  cache/history и projection semantics. Не добавлять новый публичный edge без
  отдельного design/task решения.

  W13 residual risk, а не code defect (`verification.md:70-73,122-126` и task
  card `:44,102`).
- Forecast ticker, W12 gesture/process attribution и уже зафиксированный
  repo-wide high-frequency UI finding не дублируются; здесь оставлен только
  W13-material residual механизма upstream weather projection/decode после
  изменения Main Display render path.

## Uncertainty

Собственные host/static gates W13 успешны: clean build, 56/56 full unit,
focused DisplayProjectionTest 9/9 и `git diff --check`
(`verifier-owned-evidence.md:12-20`). Профилировщик и target-device run не

видимого runtime эффекта требует отдельного измерения.
